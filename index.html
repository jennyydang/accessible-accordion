Frequently Asked Questions

An accessible accordion built with vanilla HTML, CSS and JavaScript, following the WAI-ARIA Accordion Pattern .

An accordion is a set of collapsible sections that let users show and hide related content. An accessible implementation uses a button to toggle each panel, exposes state with aria-expanded, associates the trigger and panel with aria-controls/aria-labelledby, and supports full keyboard navigation.

  • Tab / Shift + Tab — move focus between triggers
  • Enter / Space — toggle the focused panel
  • Down Arrow — move focus to the next trigger
  • Up Arrow — move focus to the previous trigger
  • Home — move focus to the first trigger
  • End — move focus to the last trigger

Yes. Each trigger is a real <button> so it is focusable and operable with a screen reader or keyboard alone. The aria-expanded state is announced automatically as it changes, and each panel is a labelled region landmark so screen reader users can jump straight to its content.

That behavior is configurable per accordion instance with the data-allow-multiple attribute on the .accordion container. Set it to "true" to let several panels stay open at the same time, or "false" to automatically close the other panels when a new one is opened.

Content Length Examples

Panels have no fixed or maximum height — the open height is measured from the actual content, so the expand/collapse animation adapts automatically whether a panel holds one sentence or several paragraphs. Open more than one below to compare.

This panel demonstrates a long-form amount of copy, spanning several paragraphs plus a list, to confirm the accordion doesn't assume any maximum content height. Because the open height comes from measuring scrollHeight at toggle time rather than a value baked into the CSS, this panel can hold as much content as a real page might need — release notes, a long FAQ answer, terms of service, or anything else that doesn't fit in a sentence or two.

Keyboard and screen reader behavior stay identical regardless of length: the panel is still a labelled region, it's still removed from the tab order via hidden while collapsed, and aria-expanded on the trigger still reflects state accurately the moment it changes. Content length only affects how tall the panel gets when open — never how it behaves.

A few reasons this matters in practice:

  • Authors can paste in real content without checking whether it will "fit".
  • Long answers don't get truncated, scroll-jailed, or clipped mid-sentence.
  • The expand/collapse timing stays consistent because it's driven by a fixed duration, not a fixed distance.
  • Nothing in the CSS sets a max-height, so there's no silent content ceiling to hit later.
